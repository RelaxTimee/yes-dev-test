##วิธีทดสอบสแกน QR Code ด้วยมือถือจริง
ถ้าพี่ๆ รันโปรเจกต์ผ่าน `localhost` ตัว QR Code จะสร้างลิงก์เป็น localhost ซึ่งมือถือจะสแกนแล้วเปิดไม่ได้ครับ ผมเลยทำระบบให้ดึง IP อัตโนมัติ รบกวนพี่ๆ ทดสอบตามนี้ครับ:
1. ต่อ Wi-Fi มือถือให้เป็นวงเดียวกับเครื่องคอมที่รันระบบ
2. หา IP Address ของคอมพิวเตอร์ (เช่น `192.168.1.X`)
3. เปิดหน้า Admin บนคอมพิวเตอร์ผ่าน IP นั้นครับ เช่น `http://192.168.1.X:3000/admin`
4. พอกดเข้าหน้าแก้ไขสินค้า ระบบจะรู้ทันทีและเปลี่ยน QR Code ให้เป็น IP นั้น พี่ๆ สามารถเอามือถือสแกนดู Mobile UI ได้เลยครับ!

## 2. Tech Stack ที่ผมเลือกใช้ และเหตุผล
- **Next.js 15 (App Router):** ผมเลือกใช้ตัวนี้เพราะผมสามารถเขียนทั้งหน้าเว็บ (React) และทำ API (Backend) จบในโปรเจกต์เดียวเลยครับ ไม่ต้องแยกโฟลเดอร์ให้ยุ่งยาก และใช้ Middleware ของ Next.js ในการป้องกันหน้า Admin ด้วยครับ
- **Tailwind CSS (v4):** ช่วยให้ผมจัดหน้าเว็บให้สวยและรองรับมือถือ (Responsive) ได้เร็วมากครับ โดยเฉพาะตอนเอาโค้ดสีแบรนด์ Luma Skin (Rose Gold, Cream) มาทำเป็น Theme Customization
- **Prisma + SQLite:** ผมเลือกใช้ SQLite เพราะพี่ๆ กรรมการจะได้ไม่ต้องเสียเวลาไปโหลด Docker หรือตั้งค่า Database Server แยกครับ แค่รันคำสั่ง `db push` คำสั่งเดียวก็มี Database พร้อมเทสงานผมได้เลย
- **Libraries เพิ่มเติมที่นำมาใช้:**
  - `xlsx`: ผมใช้ตัวนี้สำหรับแกะข้อมูลไฟล์ Excel (Import) และสร้างไฟล์ Excel (Export) เพราะมันเสถียรและจัดการโครงสร้างตารางได้ดีมากครับ
  - `qrcode.react`: ผมใช้สำหรับสร้าง QR Code แบบ Dynamic ในหน้าแก้ไขสินค้า เพราะมัน Render ออกมาเป็น Canvas ทำให้ผมเขียนฟังก์ชันกดดาวน์โหลดรูปภาพเก็บไว้ได้ง่ายครับ

## 3. สรุปฟีเจอร์ที่ทำเสร็จ
1. **อัปโหลด Excel:** นำเข้าไฟล์ สแกนเช็คข้อมูล และอัปเดตข้อมูลที่มีอยู่แล้วได้
2. **ดาวน์โหลด Excel (Export):** เพิ่มฟีเจอร์ส่งออกข้อมูลสินค้าทั้งหมดกลับไปเป็นไฟล์ Excel โดยใช้โครงสร้างเดียวกับไฟล์นำเข้า (ทำให้สามารถนำไป Bulk Edit แล้วอัปโหลดกลับเข้ามาใหม่ได้ทันที)
3. **จัดการข้อมูลที่ Error:** ถ้าราคาติดลบ หรือข้อมูลมาแปลกๆ ระบบจะยังนำเข้าอยู่ครับ แต่จะตั้งราคาเป็น 0 และซ่อนสินค้านั้นไว้ (Inactive) แล้วแจ้งเตือนให้แอดมินมาแก้ทีหลัง 
4. **ค้นหา & เรียงลำดับ (Client-side):** ผมทำตารางให้สามารถกดค้นหาหรือคลิกหัวตารางเพื่อเรียงข้อมูล ก-ฮ ได้ทันทีโดยไม่ต้องโหลดหน้าเว็บใหม่ครับ
5. **รูปภาพหลายรูป:** อัปโหลดรูปรวดเดียวได้หลายรูป แล้วผมเอาไปทำเป็นภาพสไลด์ (Carousel) ในหน้าลูกค้าครับ
6. **สร้าง QR Code:** สร้างอัตโนมัติ ปรับสีพื้นหลัง และกดโหลดรูปไปใช้งานได้
7. **เพิ่มหมวดหมู่ใหม่ได้อิสระ:** เปลี่ยนช่องเลือกหมวดหมู่ให้พิมพ์เพิ่มเองได้ ไม่ต้องง้อโปรแกรมเมอร์แก้โค้ดให้
8. **Mobile UI หน้าลูกค้า:** หน้าสแกนผมออกแบบมาให้หน้าตาเหมือนแอปมือถือครับ มีแถบเมนูด้านล่าง (Sticky Bottom Bar) ด้วย
9. **ระบบสิทธิ์ (Role):** แบ่ง Super Admin กับ Admin ตามโจทย์ครับ เฉพาะ Super Admin เท่านั้นที่ชวนคนอื่นได้

### ฟีเจอร์ที่ไม่ได้ทำ
- **การส่งอีเมลเชิญผู้ใช้ (Send Grid / SMTP จริง):** ผมใช้วิธี Print ลิงก์เชิญออกมาทาง Console Log แทนการส่งอีเมลจริงๆ ตามที่โจทย์อนุโลมครับ เพื่อความรวดเร็วและหลีกเลี่ยงปัญหา Spam/API Key หมดอายุครับ

##  5. ข้อสมมติฐานและการตัดสินใจของผม (Assumptions & Decisions)
ในระหว่างที่ทำโปรเจกต์ ผมเจอโจทย์บางจุดที่อาจจะตีความได้หลายแบบครับ ผมเลยพยายามคิดเผื่อไปถึงตอนที่ระบบนี้ถูกเอาไป "ใช้งานจริงๆ" และได้ตัดสินใจทำระบบออกมาตามเหตุผลด้านล่างนี้ครับ:

1. **ตอนที่อัปโหลด Excel แล้วเจอข้อมูลไม่ครบ (เช่น ลืมใส่ราคา หรือลืมใส่ชื่อ):**
   - **สมมติฐาน:** โจทย์สั่งว่า "ให้นำเข้าและแจ้งเตือนแถวที่ผิด" ซึ่งถ้าผมเขียนโค้ดให้ระบบเตะไฟล์ทิ้ง (Reject) ทันที พี่ๆ แอดมินคงหงุดหงิดที่ต้องกลับไปเปิดไฟล์ Excel เพื่อตามแก้ทีละจุด แล้วกดอัปโหลดใหม่หลายๆ รอบแน่เลยครับ
   - **การตัดสินใจ:** ผมเลยเลือกที่จะ **ดึงข้อมูลที่ผิดนั้นเข้า Database ไปเลยครับ** แต่ระบบของผมจะทำการป้องกันโดยเปลี่ยนสถานะสินค้านั้นเป็น `Inactive` ทันที (เพื่อไม่ให้หลุดไปโชว์ให้ลูกค้าเห็น) และใส่ชื่อชั่วคราวให้ แอดมินจะได้กดนำเข้าทีเดียวจบ แล้วค่อยมาไล่กดปุ่ม "แก้ไข" ซ่อมข้อมูลบนหน้าเว็บทีหลังได้ครับ ผมว่าแบบนี้น่าจะตอบโจทย์คนทำงานจริงมากกว่า

2. **หน้าเว็บสาธารณะ (เวลาลูกค้าสแกน QR Code เข้ามา):**
   - **สมมติฐาน:** คนที่สแกน QR Code จะต้องใช้สมาร์ทโฟน 100% แน่นอนครับ
   - **การตัดสินใจ:** ผมเลยไม่ได้ทำหน้าเว็บไซส์หน้าจอคอมพิวเตอร์ (Desktop) สำหรับหน้านี้ครับ แต่เน้นทำแบบ **Mobile-First** ให้ออกมาเหมือนแอปมือถือที่สุด มีปุ่มกดสั่งซื้อแบบลอยติดขอบจอด้านล่าง (Sticky Bottom Bar) ต่อให้พี่ๆ กรรมการเปิดหน้านี้ดูในคอมพิวเตอร์ มันก็จะบีบหน้าจอให้ดูเป็นสัดส่วนมือถือครับ เพื่อให้พี่ๆ ได้เห็น UX เดียวกับที่ลูกค้าเห็นเป๊ะๆ เลยครับ

3. **ระบบอัปโหลดรูปสินค้าหลายรูป:**
   - **การตัดสินใจ:** ตอนแรกผมลังเลว่าจะสร้างตาราง (Table) สำหรับเก็บรูปภาพแยกต่างหากดีไหม (Relation) แต่พอมองว่าสเกลโปรเจกต์ยังเป็นระบบทดสอบขนาดเล็ก ผมเลยตัดสินใจเก็บลิงก์รูปทั้งหมดเป็นก้อน `JSON String` ใส่ลงไปในตาราง Product ตัวเดิมเลยครับ วิธีนี้ทำให้ระบบทำงานได้เร็วกว่า โค้ดไม่ซับซ้อน และเวลาดึงข้อมูล (Query) ก็ทำได้ในรอบเดียวด้วยครับ แลกกับข้อเสียคือนำไปใช้กับโจทย์ที่ซับซ้อนกว่านี้ได้ยากนิดนึงครับ

## 6. การใช้ AI ในการทำงาน
โปรเจกต์นี้ผมมีใช้ AI (LLM) ช่วยในการคิดโครงสร้างและเขียนโค้ดบางส่วนที่ใช้เวลาพิมพ์นานๆ ครับ

**ตัวอย่าง Prompt ที่ผมใช้สั่งงาน AI (ประยุกต์ใช้หลักการ Prompt Engineering):**
- **System Setup & Routing:** *"สวมบทบาทเป็นผู้เชี่ยวชาญ Next.js (App Router) ช่วยเขียนโครงสร้างหน้าเว็บ Admin Dashboard ที่มีแถบเมนูด้านซ้ายล็อคความสูงไว้ (h-screen) และให้เลื่อนสกอร์ลบาร์ได้เฉพาะส่วนเนื้อหาตรงกลางเท่านั้น พร้อมทั้งเขียนโค้ด Middleware สำหรับจำกัดสิทธิ์การเข้าถึงหน้าเว็บโดยเช็คจาก Cookies ให้หน่อยครับ"*
- **Database Design (Multiple Images):** *"ต้องการอัปเดต Prisma Schema ให้รองรับรูปภาพสินค้าหลายรูป เนื่องจากใช้ฐานข้อมูล SQLite อยู่ ช่วยแนะนำวิธีที่เหมาะสมที่สุด (ระหว่างเก็บเป็น JSON Array กับสร้างตารางแยก) พร้อมเปรียบเทียบข้อดีข้อเสีย และเขียนโค้ด Next.js API สำหรับรับไฟล์ภาพหลายไฟล์ด้วย `req.formData()` ให้ทีครับ"*
- **Mobile-First UX/UI:** *"ช่วยออกแบบหน้าเว็บแสดงรายละเอียดสินค้าสำหรับลูกค้าที่สแกน QR Code เข้ามา โดยเน้นออกแบบแบบ Mobile-First 100% ใช้ Tailwind CSS คุมธีมสีสกินแคร์แบรนด์พรีเมียม (โทนสีครีม-โรสโกลด์) และขอโค้ดภาพสไลด์ (Carousel) แบบไม่ใช้ Library ภายนอก พร้อมทำปุ่มสั่งซื้อที่ลอยติดขอบจอด้านล่างเหมือนแอปมือถือด้วยครับ"*

**ปัญหาที่เจอและวิธีที่ผมแก้ปัญหาด้วยตัวเอง (Troubleshooting):**
- **ปัญหาจากการตั้งค่า Database:** ตอนเริ่มโปรเจกต์ AI พยายามติดตั้ง Prisma ให้ผมครับ แต่มันเจอบั๊ก (Telemetry Error) และพยายามรันคำสั่งผิดๆ ซ้ำๆ จนระบบ Database ค้างและติดตั้งไม่ได้
  - **วิธีแก้:** ผมตัดสินใจหยุดการทำงานของ AI แล้วเข้ามาไล่ดู Error Log ใน Terminal ด้วยตัวเองครับ สรุปว่ามันเป็นปัญหาบั๊กของแพ็กเกจ Prisma เวอร์ชั่น Beta ผมเลยพิมพ์คำสั่งจัดการดาวน์เกรด `prisma` มาเป็น v5 และรันด้วย `--ignore-scripts=false` เพื่อบังคับให้มัน Download ตัว Engine ผ่านระบบป้องกันได้สำเร็จครับ
- **ปัญหา Next.js Router Cache (Login/Logout):** ตอนแรกผมใช้คำสั่ง `router.push()` ในการเปลี่ยนหน้าตอน Login และ Logout แต่เจอว่าแถบเมนู (Sidebar) ไม่ยอมอัปเดตสิทธิ์ (Role) ตาม User ใหม่ครับ เพราะระบบ Client-side Cache ของ Next.js มันจำหน้าเว็บเก่าไว้
  - **วิธีแก้:** ผมแก้ปัญหาโดยเปลี่ยนไปใช้คำสั่ง `window.location.href` ในการทำ Login/Logout แทนครับ เพื่อเป็นการบังคับให้เบราว์เซอร์ทำ Hard Reload และดึงข้อมูลใหม่จาก Server ทั้งหมด ซึ่งแก้ปัญหาเรื่องข้อมูลสิทธิ์ค้างได้เด็ดขาด 100% ครับ
- **ปัญหาการสร้าง QR Code ให้มือถือสแกนได้จริง:** ตอนแรกตัว QR Code ถูกสร้างด้วยลิงก์ `localhost:3000` ซึ่งพอยกมือถือขึ้นมาสแกนมันจะเข้าไม่ได้ครับ (เพราะมือถือหาเครื่อง localhost ไม่เจอ)
  - **วิธีแก้:** ผมแก้โค้ดให้ระบบดึงค่า `window.location.origin` มาใช้แทนครับ เพื่อให้อ่านค่า IP Address ปัจจุบันของเครื่อง Admin (เช่น `192.168.1.X`) มาสร้างเป็น QR Code อัตโนมัติ (Dynamic) แบบนี้พอมือถือที่ต่อ Wi-Fi วงเดียวกันสแกนปุ๊บ ก็จะเข้าเว็บได้ทันทีครับ
- **ปัญหาข้อมูลตัวเลขในไฟล์ Excel (เช่น เครื่องหมายลูกน้ำ):** ข้อมูล "ราคา" ในไฟล์ Excel ที่ให้มา บางบรรทัดมีการพิมพ์ลูกน้ำติดมาด้วย (เช่น `1,500`) ซึ่งถ้าผมเอาไปแปลงเป็นตัวเลขตรงๆ ด้วยคำสั่ง Number() ระบบจะพังและได้ค่า `NaN` ครับ
  - **วิธีแก้:** ผมเขียนโค้ดเช็ค Data Type ไว้ครับ ถ้าอ่านค่ามาเป็น String ผมจะใช้ Regex `.replace(/,/g, '')` เพื่อล้างเครื่องหมายลูกน้ำออกให้หมดก่อน แล้วค่อยจับเข้าฟังก์ชัน `parseFloat` ทำให้ข้อมูลเซฟลง Database ได้อย่างปลอดภัย ไม่พังกลางทางครับ
